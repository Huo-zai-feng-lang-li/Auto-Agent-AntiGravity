# 修复模型完成通知误触发

## 目标

仅当 Antigravity 模型回复真正完成且 IDE 当前失去焦点时发送桌面通知。

## 已确认事实

- `main_scripts/full_cdp_script.js` 仅在生成状态结束并经过 2500ms 静默期后发送 `TASK_COMPLETED`。
- `main_scripts/cdp-handler.js` 只负责把 `TASK_COMPLETED` 转交宿主回调。
- `extension.js` 当前回调未检查 `vscode.window.state.focused`，因此 IDE 聚焦时也会通知。
- 提交历史显示该焦点守卫曾存在，后续被删除，构成直接回归来源。

## 方案

1. 先增加回归测试，覆盖聚焦、失焦、通知关闭和冷却期。
2. 在宿主通知回调入口读取实时 `vscode.window.state.focused` 并拦截聚焦场景。
3. 保留现有完成状态机与 5 秒去重，不把焦点判断下沉到 CDP 页面，避免跨进程状态同步竞态。
4. 执行目标测试、完整测试、语法检查和打包构建。

## 影响边界

- 触及：任务完成桌面通知的触发条件。
- 不触及：模型完成判定、自动点击、后台多标签、测试通知按钮、WPF 样式与其他统计通知。

## 完成标准

- 模型未完成：不通知。
- 模型完成但 IDE 聚焦：不通知。
- 模型完成且 IDE 失焦：通知一次。
- 通知关闭或 5 秒冷却期内：不通知。
- 全部测试与构建通过。
